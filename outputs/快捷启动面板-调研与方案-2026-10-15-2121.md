## 一、结论先行

1. 没有一款现成品能同时满足你的 6 条要求。主流启动器（Flow Launcher、Wox、ueli、Raycast、PowerToys Command Palette）全是「搜索框 + 结果列表」形态，没有「等大图标网格面板」；图标网格类产品（dock 类、Fluent Search 的 Screens）要么鼠标导向、要么闭源且功能繁杂。这个空白是真实的。
2. 形态上最接近的现成品是 Fluent Search 的 Screens（可自定义按钮面板 + 全盘搜索）。建议无论是否自研，都花半天装它试用一次：要么确认"差距可忍"省掉整个自研，要么把不爽的点记下来变成自研的需求清单。
3. 若自研，推荐组合：WPF（.NET 8）做面板 + voidtools Everything 做全盘搜索后端 + 便携 JSON 配置。理由与备选见 §四。

## 二、需求还原与接单审计

### 2.1 需求还原（你提的 6 条 → 技术解读 → 验收口径）

| # | 你的原话 | 技术解读 | 验收口径 |
|---|---|---|---|
| 1 | 快捷键呼出面板 | 全局热键 + 无边框置顶窗口，失焦自动隐藏 | 热键按下到面板可见 ≤ 100ms（实测） |
| 2 | 面板可自定义，放软件 / 文件 / 文件夹 | 磁贴数据模型：程序(.lnk/.exe)、文件、文件夹、网址、命令 | 拖入即添加、可编辑、可排序 |
| 3 | 搜索不限对象、反应一定要快 | 三层搜索：面板条目过滤 → 已装程序索引 → Everything 全盘 | 本地首结果 ≤ 50ms；全盘首结果 ≤ 200ms |
| 4 | 图标自定义、等大带边框、整齐 | 统一尺寸磁贴网格 + 细边框，图标可替换 | 视觉核对 + 列数可调 |
| 5 | 资源小、快、朴素、黑白主题 + 主题色 | 无插件系统、无动画堆砌；主题 = 明暗两套 + 一个强调色 | 空载内存 ≤ 60MB、空载 CPU ≈ 0（实测） |
| 6 | 自用、Win11、无兼容要求 | 不做安装器、不做多平台、不做旧系统适配 | 单 exe + 配置目录交付 |

### 2.2 审计：两个需要纠偏的前提

> [!warning] 这两条直接影响方案走向，先说清。

1. 「可以调用系统搜索」——Windows 自带搜索（Search Indexer）响应慢、结果不可控，接不上"反应一定要快"。现实里唯一够快的流派是 NTFS MFT 直读索引：代表是 voidtools Everything（官方定位就是"最小资源使用 + 即时搜索"✅ 官网）和 Listary 的私有索引。方案采用 Everything 作全盘后端。
2. 「可以调用 listary 之类的」——**Listary 6 没有公开 SDK / API，第三方程序无法把它的搜索结果接进自己的面板**（✅ DOPUS 官方论坛答复 + Listary 官方论坛：`--search` 命令行参数"已计划"多年未交付）。所以 Listary 只能作为独立软件与你并行使用，不能当集成后端。Everything 则有官方 CLI（es.exe，约 100 KB，走 IPC ✅ voidtools）和官方 SDK（✅），是唯一现实的集成对象。

### 2.3 审计：你没提但会踩到的事（主动提醒）

- 热键冲突：Alt+Space 常被别的启动器 / 窗口菜单占用。默认热键建议 Ctrl+` 或 Alt+Q 一类，且做成可配置；注册失败要报错，不能静默失灵。
- 中文文件名搜索：拼音首字母是高频刚需（你现在是英文文件名习惯，但"软件名/文件夹是中文"的场景躲不开）。Everything 1.5 alpha 已内置实验性 `pinyin:` 修饰符（全拼 + 首字母 ✅ 官方论坛 t=12073）；1.4 可用开源插件 IbEverythingExt（MIT，1,924 星 ✅ GitHub API）。
- 多显示器 + DPI：面板弹出位置要按显示器记忆、缩放要跟随系统，否则"手感"天天不对。
- 管理员边界：非管理员面板拉起管理员程序会正常弹 UAC，可用；反过来"管理员身份的资源管理器拖文件进非管理员面板"会被 Windows 拒绝（UIPI 系统限制），做不了，只能右键手动加。
- 开机自启：HKCU Run 注册表即可，不需要管理员权限。
- 你有两台电脑（ZDX 与另一台）：exe 放各自本机，配置放群晖同步目录即可双机共用一份配置（我加的建议，见 §4.7）。

## 四、自研方案（推荐稿）

### 4.1 总体架构

```
托盘常驻（单实例互斥）
 ├─ 全局热键 → 显示/隐藏面板（无边框、置顶、失焦即隐、Esc 即隐）
 ├─ 面板窗口 = 搜索框 + 磁贴网格（等大、细边框、圆角）
 └─ 搜索三层（全部异步）
     ① 面板条目过滤（内存索引，毫秒级）
     ② 已装程序索引（开始菜单 .lnk + 注册表 Uninstall，启动时建 + watcher 增量）
     ③ Everything 全盘（es.exe 子进程，防抖 100ms，结果流式上屏）
配置：便携 JSON（exe 旁 config\ 目录）
```

### 4.2 技术选型对比（推荐 WPF）

| 方案 | 空载内存 | 热键→面板 | 打包 | 开发与维护 | 结论 |
|---|---|---|---|---|---|
| WPF / .NET 8（self-contained 单文件） | 约 40–80MB ⚠️典型值 | ≤100ms 可达 | 单 exe（盘占约 80–150MB） | Win32 集成一等公民：热键/托盘/拖放/图标提取/UAC 全是系统级支持 | **推荐** |
| Tauri 2（Rust + WebView2） | 约 30–60MB ⚠️估计 | ≤100ms 可达 | exe 仅 5–10MB | UI 用网页技术最灵活；但拖放/图标提取/托盘都要装插件，Rust 侧排错成本高 | 备选 |
| Rust 纯原生（egui / Slint） | 约 10–30MB ⚠️最小 | 快 | 单 exe 5–15MB | 资源最优，但 UI 全手工，改观感最慢 | 资源极致优先时选 |
| AutoHotkey v2 GUI | 极小 | 快 | 脚本 | 一两天能出糙版 MVP；主题/网格/持久化难打磨 | 只当快速验证，不当正式版 |
| Electron（uTools/ueli 路线） | 200MB+ ⚠️ | 慢 | 大 | — | 否决：直接违背你的资源要求 |

> [!ai] AI 提炼（选型判断，依据如下，不是事实陈述）：你的使用模式是"长期自用 + 由 agent 迭代维护"，所以选型权重 = 资源达标 > Windows 集成省事 > agent 改起来快 > 盘占体积。WPF 在这四项上平衡最好：磁贴网格/边框/主题在 XAML 里直接写；资源管理器拖入、exe 图标提取、托盘、UAC 都是框架原生能力，不用造轮子。盘占 100MB+ 是它唯一明显扣分项，但你对盘占没提要求。

### 4.3 搜索设计（对应你的第 3 条）

- 三层结果合并展示，排序规则固定：面板条目 > 已装程序 > 全盘文件。
- 防抖 100ms + 异步：打字期间绝不阻塞 UI，Everything 结果到一批上一批。
- 拼音首字母：两条路线，拍板后二选一——
  - A：Everything 1.5 alpha 自带 `pinyin:` 修饰符（官方实验性 ✅），零开发量；
  - B：自建"汉字→拼音首字母"映射表（思路抄 IbEverythingExt），只作用于文件名，内存开销可控，不依赖 alpha 版。
- 网页搜索入口（可选功能）：只接 Bing / Google / DuckDuckGo / GitHub 四个（你的全局白名单）；百度及同类**从代码层不做**，不是配置里删掉。

### 4.4 面板与交互（对应你的第 2 / 4 条）

- 磁贴：等大网格，列数可调（如 6 / 8 / 10），磁贴 = 图标 + 名称，统一 1px 细边框 + 小圆角；名称过长截断 + 悬停全名。
- 添加：平时从资源管理器把 exe / .lnk / 文件 / 文件夹**拖进面板即添加**（WPF 原生 OLE 拖放）；也有右键手动添加兜底（应对管理员窗口拖不进来的系统限制）。
- 编辑模式：一个开关进入，拖拽排序、拖出删除、右键改名/换图标/改类型；退出即锁定。
- 图标：默认提取目标真实图标（Win32 标准能力）；右键"更换图标"可指定 .ico / .png。
- 条目类型：程序、文件、文件夹、网址、自定义命令（如"在此处打开终端"）。
- 多页：翻页或标签页，二选一，P1 做基础版时可先用"单页 + 滚动"顶住。
- 行为：记住上次位置与所在显示器；再按热键 / Esc / 点击面板外 → 隐藏；托盘左键 = 呼出。

### 4.5 主题（对应你的第 5 条）

- 明 / 暗两套底色，一个强调色（取色器 + 预设几个朴素色：灰蓝、墨绿、砖红之类）；配置即 JSON，两个键搞定，绝不做皮肤系统。

### 4.6 性能验收指标（交付时给实测数字，不说"已优化"）

| 指标 | 目标 |
|---|---|
| 冷启动到托盘就绪 | ≤ 2s |
| 热键按下 → 面板可见 | ≤ 100ms |
| 空载内存（托盘常驻、面板隐藏） | ≤ 60MB |
| 空载 CPU | ≈ 0%（无后台轮询，只有事件驱动 + 文件夹 watcher） |
| 面板内过滤首结果 | ≤ 50ms |
| Everything 全盘首结果 | ≤ 200ms |
| 交付物 | 单 exe + config 目录，无安装器，免管理员运行 |

### 4.7 配置与双机同步（我加的建议）

- exe 放各机本地（程序不同步），config\ JSON 放群晖同步目录 → 两台电脑共用一份布局与设置；图标缓存放本机（缓存不进同步盘）。

## 五、功能建议（以下全部是我加的，采不采纳你定）

1. 拼音首字母搜索（§4.3，最推荐，中文环境几乎是刚需）。
2. 网页搜索入口（白名单四引擎，回车直达）。
3. "固定区"：面板顶部一行钉最常用项，下面网格自由摆放（借鉴 CmdPal Dock 的概念）。
4. 顺序稳定原则：不做"按使用频率自动排序"——你手动摆的布局不动才叫整齐，自动排序是复杂化，不建议。
5. 文件夹磁贴"面板内展开"：点文件夹先在面板里列出子项，再决定打开还是进入，少开一层资源管理器。
6. 配置即 JSON：天然可备份、可同步、可进 git。

不建议做（违背朴素 / 低占用）：插件系统、皮肤市场、在线服务、AI 功能、常驻动画特效。

## 六、风险与代价（主动提醒）

1. 自研 = 长期绑定 agent 维护。Win11 单平台、无兼容包袱，功能冻结后维护成本低；但改需求就是"找我改代码"的模式，你要接受这个闭环。
2. Everything 是外部依赖：需要安装并常驻（可装服务模式，开机静默；它本身极轻）。若你连它都不想装，方案退化为"只搜程序 + 面板条目"，全盘搜索砍掉——这是 §七 问题 3。
3. Everything 1.5 仍是 alpha（小众软件 2026 年报道其"进入全面稳定期" ⚠️ 媒体口径）；不想用 alpha 就走 1.4 + IbEverythingExt 或自建拼音映射（§4.3 路线 B）。
4. 热键被占用时的表现要在设置里明确报错，不能静默失灵——这类"没反应"最耗排查时间。
5. 里程碑工作量（⚠️ 我的估计，供预期管理）：P0 一次会话；P1 / P2 各约 1–2 次会话；P3 / P4 各约 1 次会话。全程按你 3–7 小时/周的业余节奏推进，主要是你验收的节奏，不是我写代码的速度。
